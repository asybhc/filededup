# 相似图片判定（M3）

本文记录相似图片判定的实现口径、与原版的一致性状态，以及 `skipUniform` 退化指纹规则。

## 1. 支持格式

| 扩展名 | 解码器 | 与原版（GDI+）一致性 |
| --- | --- | --- |
| jpg / jpeg | 标准库 `image/jpeg`（含 EXIF Orientation 1–8 归一） | 逐位一致 |
| png | 标准库 `image/png`；解码失败时对截断文件做宽松部分解码（见 4.5） | 逐位一致 |
| gif | 标准库 `image/gif`（取首帧） | 逐位一致 |
| bmp | 本包自实现（24/32 位） | 逐位一致 |
| tif / tiff | `golang.org/x/image/tiff`（纯 Go） | 与 GDI+ 生成的样本对拍一致 |
| webp | `golang.org/x/image/webp`（纯 Go） | **原版不支持**（GDI+ 对 webp 一律解码失败），Go 侧为超集能力，无法对拍 |

不允许 HEIC/RAW：原版也不支持，且没有纯 Go 解码器。

## 2. 指纹算法

1. 按 EXIF Orientation(274) 归一：5–8 时先按行列互换的尺寸绘制，再旋转/镜像回正。
2. 缩放到 9×8、白底、24 位画布。缩小、放大统一用三角核：半径 = `max(1, 缩放比)` 个源像素，
   目标像素中心取 `(x+0.5)×缩放比`，源图外按白底加权（详见 4.3、4.4）。
   只有两轴同时 1:1 时才按纯拷贝处理。
3. 8 行 × 8 列，灰度 `(R*299+G*587+B*114)/1000` 取整，左侧大于右侧时置位，`bit = row*8+col`。
4. 分组：按路径（忽略大小写）升序，贪心锚点 + 组内直径约束——新成员与锚点、与每个已加入
   成员的汉明距离都必须 `<= 阈值`（默认 8）。

全部语料逐位一致，包括此前登记的 `04-images/corrupt.png` 与 `04-images/tiny-1x1.png`
（见 4.4、4.5）。

## 3. 退化（均匀）指纹规则 `skipUniform`

### 3.1 问题

纯色图归一化后每行相邻灰度相等，理论上 dHash 全 0。但白边会让最左（及最右/上下）一列变亮，
实际指纹恒定落在 `0x0101010101010101` 一类，纯白图还会因浮点截断得到 `0x2828282828282828`。
结果是互不相关的红色、蓝色、黑色纯色图被判成"相似"，形成假阳性组。

### 3.2 判定

`image.Compute` 在算指纹的同时返回 `Uniform`：

- 取归一化画布 **去掉 1 像素白边后的内部区域**（9×8 画布即 x∈[1,7]、y∈[1,6]）；
- 若内部灰度极差 `<= 1`，判定为退化指纹（纯色、纯色条、没有行内明暗变化的图）；
- 判定不看指纹数值，因此不受白边与浮点截断影响。

### 3.3 开关

| 位置 | 名称 | 默认 |
| --- | --- | --- |
| CLI | `fdedup scan --image-skip-uniform` | 关闭 |
| JSON 请求 | `similarImage.skipUniform` | 关闭（`false`） |

默认关闭＝与原版完全一致（纯色图仍会被合并）。默认值最终由产品口径决定，改动时只需改默认值，
无需改算法。

### 3.4 日志与输出

开启后，被排除的图片不进入相似分组，并在结果 `skipped` 中逐条登记：

```json
{ "path": "...", "code": "uniform_fingerprint",
  "message": "图片无行内明暗变化（纯色图/纯色条等退化指纹），按 skipUniform 规则不参与相似分组" }
```

`fdedup scan` 的文本摘要会额外打印一行：`退化指纹未参与相似分组：N 个（--image-skip-uniform）`。

注意：这些文件仍参与**精确查重**（`--exact`），规则只影响相似图片分组。

  截断 PNG 宽松解码、TIFF↔PNG 一致性、WebP 解码与截断容错、分组拆组、EXIF、BMP）、
  `internal/engine/similar/audio`。

### 4.2 已修复：纯白图指纹偏差

C 批次曾暴露一处新差异：纯白图 C# 得 `0000000000000000`，Go 得 `2828282828282828`。
原因是面积平均得到 `254.9999…`，被灰度公式截断成 254，凭空造出梯度位。
现在 `normalize` 末尾把 9×8 画布通道就近取整（GDI+ 全程是 8 位整数），偏差消除且 A 批次结果不变。

### 4.3 已修复：大比例缩小时的预滤波核

E 批次曾暴露 2 条差异（各 10 位）：`build/appicon.png` C# `011397970f2b2b03` / Go `039296968a2a2b01`，
`logo-universal.png` C# `63431f1f1f1f1f3c` / Go `674318561f1f1d30`。

已用实验排除透明通道：把两张图先按白底压平成不透明 PNG 后重新对拍，C# 与 Go 的指纹都一字不变，
说明两边都把透明像素合成为白底，差异不在 alpha。

根因是**缩小方向的预滤波核**。为拿到证据，给 C# 参考程序加了一条只读诊断
`--dump-canvas-json <out.json> --canvas-image <path>`（`B/ScanDump.cs`），直接反射调用原版
`a.q.A_m_1(Image,9,8)` 导出 9×8 画布。纯黑 1024×1024 的实测画布（红通道）：

```
 59  32  32  32  32  32  32  32  61
 31   0   0   0   0   0   0   0  33
 ...（中间 0，左右边 31/33）
 59  32  32  32  32  32  32  32  61
```

边 31–33 表示单轴约 12.5% 的白渗入，角 59–61 恰为 `1-(1-0.125)²`，说明越界按白底参与加权；
而面积平均（box）在纯色图上给 0，只能靠人工叠白边（旧实现里的 `edgeWhite=0.129`）伪造，
内部像素更是完全无法解释 appicon 的偏差。按半径扫描拟合后，模型为：

1. 统一用**三角核，半径 = `max(1, 缩放比)` 个源像素**（缩小方向半径即缩放比，放大方向固定为 1）；
2. 目标像素中心在源轴上的坐标取 `(x+0.5)×scale`，**不减半像素**；
3. 源图外的核权重按白底（255）计入；
4. 水平、垂直两趟之间，中间结果**取整到 8 位**（GDI+ 两趟缩放落 8 位缓冲）。

第 4 条是必要的：不取整时纯竖向渐变 `gradient-v-256.png` 会因浮点累加顺序翻转 1 位。
该模型对全部 10 张缩小样本的逐格画布与 C# 灰度差 ≤1、指纹全部一致。旧实现里针对放大轴的
`edgeWhite=0.129` 人工白边只是这个核在 1:1 轴上的边缘白渗入的近似，已在 4.4 中由统一核取代。

修复后 E 批次两张图的汉明距离 10 → 0，A/B/C/D 四批当时的一致条数不变，13 组场景与扫描层对拍结果不变。
回归护栏：`TestHashLargeDownscaleGDIPlus` 固定这两张图的 C# 指纹。

### 4.4 已修复：极小图放大时的整体掺白（`tiny-1x1.png`）

A 批次曾登记 `04-images/tiny-1x1.png`：C# 得 `0f0f0f0f0f0f0f0f`，Go 得 `0101010101010101`。
1×1 放大到 9×8 时 GDI+ 会整体掺白（中心实测掺白约 43%），旧的"双线性 + 最外圈叠白"无法解释。

用纯色小样本（1×1…8×8、1×8、8×1、2×8、8×2、1×16、16×1）经 `--dump-canvas-json` 导出 C# 画布后，
一维白占比曲线被同一模型完整解释，即 4.3 的三角核：

- 放大方向半径固定为 **1 个源像素**（不是缩放比），例如 1→9 的列中心白占比 `0.251`、
  边缘 `0.447`，与 `p=(x+0.5)/9`、半径 1 的三角核预测逐点吻合；
- 某一轴恰好 1:1、另一轴缩放时，1:1 轴仍走同一条滤波路径，产生约 `1/8` 的边缘白渗入
  （纯黑 8×8 → 9×8 的首末行即为此现象）；这是旧 `edgeWhite` 的真实来源；
- 两轴同时 1:1 才是纯拷贝（对应 C# 第二趟 `DrawImage` 的直通）。

因此 `tiny-1x1.png` 的指纹天然变成 `0f0f…`。回归护栏：`TestHashTiny1x1GDIPlus`。
全部 22 个小样本的 C# 画布与 Go 画布指纹一致（逐格灰度差 ≤2，仅出现在取整边界）。

### 4.5 已修复：截断 PNG 的宽松解码（`corrupt.png`）

A 批次曾登记 `04-images/corrupt.png`：C# 用 `validateImageData:false` 仍出指纹
`01010101117f7f7f`，Go 侧标准库解码失败进入 Skipped。

实测该文件为 256×256 8 位 RGB，IDAT 声明 1074 字节但文件仅 377 字节（IDAT 实际可用 336 字节，
无 IEND/CRC）。宽松模式的行为是：**不校验 CRC 与完整性**，对 IDAT 做"能解多少解多少"的 zlib 解压，
只采用完整的扫描行（本例 83.5 行 → 83 行），其余行按**不透明黑**填充后照常缩放。

Go 侧新增 `pngpartial.go`：严格 `png.Decode` 失败后，按扩展名 `.png` 回退到部分解码
（非隔行、8 位深、颜色类型 0/2/4/6；其他情形如实按解码失败处理）。用该路径复现的画布
与 C# 逐格灰度差 ≤1、指纹 `01010101117f7f7f` 完全一致。回归护栏：`TestHashTruncatedPNGGDIPlus`。

修复后 A 批次图片 16/18 → 18/18，不再有登记差异。

## 5. 纯色图合并：默认值待定

按当前默认（`skipUniform=false`），纯色图仍会与其他无梯度图片合并为一组，与原版行为一致。
是否改为默认开启由产品口径决定；确定后只需把 CLI 开关默认值与 `similarImage.skipUniform`
的缺省值改为 `true`，规则本身与对拍基线不受影响。
